# Casper Flow — marketing site

Six routes:

| Route | Purpose |
|---|---|
| `/` | Landing page |
| `/guide` | Full download-to-first-sentence walkthrough |
| `/alternatives/wispr-flow` | Comparison page, targets "free open source alternative" |
| `/privacy` | Privacy, including what this website itself does |
| `/terms` | Terms of use |
| `/download` | Redirect to the release asset. `noindex`, absent from the sitemap. |

## Stack

| | |
|---|---|
| Framework | TanStack Start (file-based routing, SSR) |
| Build | Vite 8 + Nitro |
| Hosting | Vercel. Root Directory must be set to `website` in the dashboard. |
| Styling | Tailwind CSS 4, design tokens in `src/styles.css` |
| Fonts | Instrument Sans, JetBrains Mono (Google Fonts) |
| Icons | none — the site uses type and composition, not icon sets |

## Develop

```sh
npm install
npm run dev     # http://localhost:5173
npm run build   # production build
npm run lint
```

## Facts, not placeholders

`src/components/site/constants.ts` exports `SITE` and `ACCURACY`: every value the
site asserts, in one file. It used to export a `PLACEHOLDER` object whose values
rendered literally on the page, because there was no installer to describe yet.

The sizes, checksum and version now come from the artefacts
`build_installer.ps1` produces. When a release ships, these change together:

```
version  installerSize  installedSize  portableSize  sha256
```

**Three values are still assumptions**, and each is marked in the file: `domain`,
`repoUrl` and the absence of a published release. `domain` is duplicated into
`public/sitemap.xml` and `public/robots.txt` — CI fails the build if the three
disagree, which is what keeps that duplication honest.

CI also fails if the string `[PLACEHOLDER` survives into the build output.

## Generated assets

Three files in `public/` are generated from code in the repository root, not drawn
by hand, so they cannot drift from the application:

| Asset | Generated by |
|---|---|
| `favicon.ico` | `make_icon.py` — the same nine frames as the app icon |
| `og.png` | `make_og_image.py` — 1200x630 social card, reuses `draw_mark` |
| `overlay/*.png` | `make_overlay_previews.py` — imports the app's own `pill_render` |

`overlay/` matters most. The overlay was previously hand-drawn in SVG and was
wrong in every particular: the wrong colour, the wrong shape, and none of the
waveform detail. Those PNGs are now produced by the same renderer the running
application uses. Re-run the script after any overlay change.

## The download counter

`downloads.ts` sums `download_count` across every published release asset via the
GitHub API. Three deliberate properties:

- **Server-side only.** A browser fetch would hand every visitor's IP to GitHub,
  which is indefensible on a site arguing that it does not send your data to third
  parties.
- **Returns `null`, never `0`.** No release exists yet, the API is rate limited,
  and networks fail. The homepage renders nothing rather than advertising that
  nobody has downloaded it. It appears on its own once a release is published.
- **Cached for 30 minutes** in module scope, or trivial traffic would exhaust the
  unauthenticated rate limit.

## Design rules

The rules that matter most when editing copy:

- Sentence case headings. Never Title Case.
- No emojis, no exclamation points, no rhetorical questions as headings.
- No invented statistics, testimonials or customers. Accuracy figures are
  permitted only because they are measured — they live in `ACCURACY` and come from
  the corpus in `corpus/`, and the missed 90% Hinglish target is stated as missed.
- Banned marketing vocabulary: revolutionize, unleash, supercharge, seamless,
  effortless, game-changing, cutting-edge, elevate, transform your workflow,
  powered by AI, say goodbye to.
- **Every claim must be true of the shipped application.** This is the rule that
  has been broken most often: an audit against the shipped defaults found five
  false claims on the homepage, including an overlay style that does not exist.
  Check `settings.json` before describing behaviour.
- Animate only `transform` and `opacity`. Reveals fire once, via
  IntersectionObserver, and respect `prefers-reduced-motion`.
- Content must be readable with JavaScript disabled: reveal styles apply only
  after the `js-reveal` class is set, and the FAQ accordions are native
  `<details>` elements.

## Accessibility

One `h1` per route, semantic landmarks, visible focus states, WCAG AA contrast,
meaningful `alt` text on product visuals and empty `alt` on decorative ones. The
footer wordmark is `aria-hidden` — it is texture, not content.

Full WCAG conformance is not claimed: that needs manual testing with assistive
technology and expert review, neither of which has been done here.
